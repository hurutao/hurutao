# 《魔兽训练场》V1 开发计划 · 审批稿

**下一项可运行交付是 G2。** 从 Windows 桌面正常启动现有 FPSArena 工程，进入原创灰盒祭盘，使用键鼠或手柄移动、切换肩位与第一 / 第三人称，再退出并恢复配置。负责人批准 G1 三份文档后开始实现。

## 工程起点与关键选择

| 决策 | 依据、备选与风险 |
| --- | --- |
| 沿用 FPSArena 工程和单一运行模块 | 受检基线为 `1f5fe2ff6bfa2225ba9a986f37f978b8468511c8`。已有角色、镜头、输入修饰器、基础命中、回合和 SaveGame。按 Input、Character、Practice、Targets、Combat、Settings、UI、Platform、Core 职责逐步整理；仅在平台依赖需要隔离时拆模块。重建工程会丢失已实测基线。 |
| 先打通正常入口 | `Config/DefaultEngine.ini` 默认加载 FirstPerson 模板；`Scripts/PlayTraining.ps1` 通过 Entry 与 RangeGameMode 覆盖进入原型。G2 先用两入口对照，再将正式游戏默认地图与模式指向灰盒。验收走正常启动；脚本保留作诊断。 |
| 先完成一次可重复训练，再扩展模式 | 原型的 `RangeBest_v1` 存最高命中数，新版 M1 判据为进环并持续保持。旧记录标记为原型规则，保留原始类型；新规则单列版本和历史。复用镜头、命中与回合保护，避免把模板命中数折算成新评分。 |
| 原生离线优先，Steam 增量接入 | G2 开始验证 DualSense 离线基础输入。Steam 客户端与高级反馈放在平台适配层，通过能力状态降级。若某基础设备路径不能实测，列为对应交付缺口。具体互斥规则见[输入技术方案](../Research/Input_Technical_Design.md)。 |
| 原创灰盒 → 玩法 → 手感 → 美术 → 性能 | G2–G6 分段扩充同一张图。G8 替换外观时沿用碰撞与训练坐标。先用 UE 基础体或原创程序化资产；商业素材逐项登记作者、来源、授权与限制。[灰盒布局与验收](../Research/Training_Arena_Layout.md) |

## 训练规则如何落到验收

以下是用于首轮实现及测试夹具的建议值，G3–G5 完成人体手感测试后再冻结。普通预设默认辅助关闭。每局生成唯一会话 ID 与规则版本，记录种子、设备、输入路径、视角、FOV、难度和辅助参数。只有条件一致的成绩默认同组比较；中途切换设备、视角或辅助参数的局单独标记。

| 模式 | 单局起止与目标规则 | 必须输出的指标和反例 |
| --- | --- | --- |
| M1 精确定位 | 倒计时后连续出现 10 个种子环；首次连续保持 300 ms 完成该环，单环 3 s 超时进入下一个 | 每环首次进入时间、连续保持成功率、平均角误差及总时长；进入后马上划出不算保持成功。 |
| M2 拉直线 | 30 s 水平 / 竖直分段移动，种子决定首方向与折返时刻 | 时间加权平均角误差、在靶时间比、角误差时间积分（度·秒）；静止准星应在目标离开时失去在靶状态。 |
| M3 缓慢微控 | 30 s 固定种子低速漂移，位置连续，边界折返 | 时间加权角误差、屏幕误差（像素距离 / 视口高度）、在靶时间比；切换分辨率时归一化结果应一致。 |
| M4 对角拉线 | 30 s 双向对角段；锁定起始相机投影，轨道按等比例像素轴 45° 生成 | 跟踪误差、在靶时间比、垂直于轨道的偏差；16:9、16:10 分别量角。 |
| M5 综合挑战 | 给定种子将 M1–M4 各一段排列，显示本段规则，四段完成或到各自上限即结算 | 记录种子、段序、各段原始指标与总分；同版本重试应逐段一致。 |
| M6 精细走位 | 穿起点门开始，按序过检查点并到终点或 60 s 超时 | 碰撞次数按接触开始计、路线偏离距离积分、完成用时；靠墙持续接触只记一次。 |
| M7 定点停靠 | 过加速门开始，到达圈内低速稳定 0.5 s 或 15 s 超时 | 沿行进方向的最大过冲、进入后稳定时间、最终离圈心距离；冲过圈后返回仍保留过冲值。 |
| M8 身法连段 | 过起点按提示完成冲刺、急停、滑铲、跳跃，完成末段或 30 s 超时 | 正确动作比例、相对提示时间误差、段用时；按键边沿加角色状态变化判定，乱序与重复输入留痕。 |
| M9 摇杆协同 | 30 s 沿路线移动并跟踪目标；射击变体要求命中，固定种子生成轨迹 | 移动轨迹、路线偏差、可见时段准星误差、命中率或纯跟踪标记；同时满足移动与瞄准要求的时间占比单列。 |

**计分基线。** 通过率类指标直接取 [0,1]，误差 / 时间类用质量函数 q(x,b)=clamp(1−x/b,0,1)，b 是各难度配置的零分界限，须随规则版本入档。首版普通难度建议角误差界限 6°、首次进环 3 s、屏幕误差 0.12 个视口高度、平均路线偏离 1 m、停靠误差 2 m、过冲 3 m、稳定时间 3 s、动作时序误差 0.5 s、碰撞 5 次。M1 超时的环按 3 s 与保持失败计；M6–M8 超时按已完成比例折减，零进度为零分。分母为空的指标标记不可用，规则另有规定的按规定计。积分统计使用有效时间；菜单或暂停期间冻结训练时钟。

各模式先计算 0–1 的子项，再按下表加权乘 100，四舍五入到整数。首次验收建议 D 为 0–39，C 为 40–59，B 为 60–74，A 为 75–89，S 为 90–100。测试夹具覆盖每个临界点及其前后一分。

| 模式 | 初版权重 |
| --- | --- |
| M1 | 50% 保持成功率 + 30% 首次进入质量 + 20% 平均角误差质量。 |
| M2 / M4 | 60% 在靶时间比 + 40% 平均角误差质量。轨迹偏差积分另行展示。 |
| M3 | 50% 屏幕误差质量 + 50% 平均角误差质量。 |
| M5 | 四段各占 25%，直接使用相应模式的百分制分数求均值，最后取整。 |
| M6 | 50% 路线质量（积分除有效时间）+ 30% 碰撞质量 + 20% 用时质量（界限 60 s）。 |
| M7 | 40% 最终误差质量 + 35% 过冲质量 + 25% 稳定时间质量。 |
| M8 | 70% 正确动作比例 + 30% 时序质量，漏做的动作该项贡献为零。 |
| M9 | 50% 同时达标时间占比 + 25% 路线质量 + 25% 命中率（射击变体未开火为零；跟踪变体用在靶时间比）。两变体分别排行。 |

原始观测按实际时间戳保存，60 Hz 时间轴用于对齐与分析。每局可当场重试、查看历史并比较误差曲线；主动放弃存为中止记录，独立于正常完局评级。成绩写入按会话 ID 幂等。设置与成绩文件验证版本、范围、有限数值和必填字段，安全替换、备份回读和崩溃重试均纳入测试。

## 每个工程交付的验证与留档

1. 使用项目规定的 UBT 命令构建 FPSArenaEditor Win64 Development；涉及头文件或 Build.cs 时执行完整重编并确认零错误。用 UnrealEditor-Cmd 运行 FPSArena 自动化，同时读匹配数量、逐项结果与退出码。每阶段另从正常入口完成一遍玩家流程。
2. 用固定输入记录、布局版本和随机种子跑两遍。核查 30 / 60 / 120 FPS 的分数、动作次数及相机积分；模拟输入单独记录。软件读入至状态更新使用同一单调时钟。端到端延迟留给外部测量。
3. G8/G9 在 1920 × 1080、固定画质与渲染比例、记录垂直同步和帧上限的条件下，预热后按同路线采三次各 120 s，保留原始帧时间。报告平均 FPS、平均及 P95 帧时间、超过 50 ms 的帧数与最长帧。目标平均 ≥60 FPS；如某台设备未测则标 UNVERIFIED。记录 GPU 完整型号、驱动、功耗模式和构建哈希。
4. 每个 G 阶段在 `Docs/Reports/Milestone_GX.md` 归档变更、工程和文档仓库相应哈希、命令、退出码、人工步骤、硬件、缺陷、未完成项与后续动作；测试标 PASS / FAIL / BLOCKED / UNVERIFIED。G9 放行要求所有必需功能有证据，已知阻断级崩溃清零。
